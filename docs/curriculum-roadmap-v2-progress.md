# Curriculum → Student Roadmap (v2) — Progress

Audit: `docs/curriculum-roadmap-audit.md` (Phase 0). Earlier job-track work: `docs/curriculum-roadmap-progress.md`.

## Decisions (approved 2026-10-06)
1. Canonical skills: **extend the existing `skills` table in place**; the 146 old free-text rows become `candidate` (never resolved, never mapped to).
2. Careers: new normalized `careers` / `career_skill_requirements`; legacy `career_requirements` kept until Career Path / Skill Gap migrate.
3. Hierarchy: keep `institutions` + branch text; regulation lives on the import. No University/Program/Branch tables.
4. Capabilio admin: operator-only (SQL/seed scripts) for taxonomy, careers, catalogs, skill-suggestion review. No platform-admin UI.
5. Roadmap shows for **all tracks that have a career goal** (lifts the job-track-only gate).
6. Capability level: `capabilities.capability_score` is the source of truth where present; Arena-only skills get a documented, explicit count→level formula (to be written in Phase 5).

## Phase 3 — Ingestion upgrade: DONE
- **Deterministic first.** `lib/roadmap/extract/section.ts` reads each course section into objectives, outcomes (code + Bloom level from the printed K-tag), units, topics, lab experiments, prerequisites, L-T-P-C, textbooks, reference books, online resources — copying text, inventing nothing, with a raw-snippet provenance per field. `programs.ts` reads PO/PSO statements and the regulation/program from the running header. Verified against the real JNTUK R23 CSE PDF.
- **AI only where needed.** `structureCourseSection` (in `suggest.ts`, the sole AI gateway) reads a section the parser could not; every item it returns is dropped unless found word-for-word in the section (`enrich.applyFallback`), capped at 12 sections per upload. It ran **0 times** on the real PDF (the parser handled every section), so that path is unit-tested only.
- **Saved as a draft import.** `persist.ts` writes one `curriculum_imports` row (status EXTRACTED, invisible to students) with the whole tree (courses, outcomes, units, topics, labs, POs/PSOs, textbooks…); a failed save deletes its own draft and is retried once; discarding the staged extraction soft-deletes the unpublished draft. Migration **051** links `curriculum_extractions.import_id`. The legacy review UI is unchanged and still works.
- **Skill suggestions are a separate, explicit, resumable step** (`suggest-skills.ts` + `POST /api/admin/curriculum/imports/[id]/suggest-skills`): 12 courses per request, canonical catalog only, every candidate needs evidence found in the course's own text, names are resolved with `resolveSkill`, unresolved names go to `skill_suggestions` (never into `skills`), course-level AND outcome-level mappings stored as SUGGESTED / AI_SUGGESTED, a CONFIRMED or REJECTED mapping is never touched, idempotent. Running it inside the upload took 479 s (> the 300 s route limit), which is why it is separate.
- **Real-AI result (JNTUK R23 CSE, live model):** upload 108 s → 61 courses, 143 outcomes, 249 units, ~2.9k topics, 203 experiments, 15 POs/PSOs, regulation R23 / B.Tech, no warnings. Suggestions: 5 requests of 12 courses (44–94 s each) → 115 course-level and 154 outcome-level mappings over 52 courses, all SUGGESTED/AI_SUGGESTED; unresolved names queued (e.g. "Design Patterns", "IoT Connectivity", "Environmental Science Knowledge"). Test-run queue entries and fixtures were deleted afterwards.
- **Bugs found by real runs and fixed:** the extraction's final "ready" write (and progress writes) ignored errors, so a dropped connection left a finished job stuck on "processing" — now retried and thrown (progress stays best-effort); a swallowed draft-save failure is now logged and retried; `L T P C` trailing the title line, unstated credits (`-`) kept null; duplicate "UNIT I" in a merged section renumbered; a mark-as-processed write now checked.
- **Tests:** 17 section/programme parser tests on the real PDF, 10 enrich/grounding tests, 6 live suggest-skills tests (stubbed AI), extended live extraction tests (import saved with the right tree, nothing published or confirmed, discard soft-deletes the draft), guard tests (extraction can only write AI_SUGGESTED/SUGGESTED; only `suggest.ts` imports the AI provider). 530 unit tests, `tsc` and eslint clean.
- **Known limits:** topic splitting is a heuristic on commas/semicolons (some topics are merged/over-split); the parser's headings were verified on one university's layout (others fall back to the AI structurer or are reported as unread); ~1 in 3 live-test runs hit a local `fetch failed` transport error.

## Phase 5 — Careers, intent, capability, relevance: DONE
- **Migration 054** (applied). `careers` + `career_skill_requirements` (canonical skill ids; importance CRITICAL/HIGH/MEDIUM/LOW, target 0–100, stage FOUNDATION/INTERMEDIATE/JOB_READY; a trigger refuses a requirement on a non-active skill), `student_career_intent` (primary, Plan B, exploring, goal text), `career_suggestions` (PENDING/ACCEPTED/DISMISSED), `institution_memberships.regulation`. Catalog is world-readable; a student's intent/suggestions are read-own; **nothing is client-writable**. 10 careers: the 8 starter ones plus Business Analyst and Product Designer from the legacy table. The legacy `career_requirements` is untouched and still feeds Career Path / Skill Gap.
- **Seed data is product-team-review starter data** (names, requirements, importance, targets). Legacy backfill resolves skill names by **exact** alias/name match only; the one name that didn't resolve ("Vocabulary") was queued in `skill_suggestions`, not guessed. Importance for backfilled requirements is banded from the legacy number (≥85 critical, ≥70 high, ≥55 medium, else low).
- **Derived career relevance** (`lib/careers/relevance.ts`, pure): share of a career's weighted demand (importance × target level) that a course's CONFIRMED skills cover, weighted by how strongly the course teaches each skill; HIGH ≥ 20 %, MEDIUM ≥ 8 %, LOW > 0, else no match, with the skills that drove it. Shown on every course page ("Why?" expands the explanation) and in the wizard's Career relevance step (per career, best courses first). With no confirmed skills it says so instead of claiming a result. It never changes what a student is told to study.
- **Capability read model** (`lib/capability/read-model.ts`): per canonical skill, over the EXISTING data — `capabilities.capability_score` stays the source of truth; Arena-only skills use the documented formula **25 level points per verified task (cap 100)**; verified and self-declared evidence are tracked separately (self-declared is capped at 40, carries no confidence and never outweighs verified). The `evidence` table is not read separately (it already feeds `capabilities`; adding it would double count). Capability names that don't resolve are listed as unmatched, not dropped silently. **No self-declared source exists in the product today**, so that side is modelled and tested but empty.
- **Student career intent** (`lib/careers/intent*.ts`, routes `/api/career-intent`, `/suggest`, `/suggestions/[id]`): the student's own explicit choice of main career, Plan B and "I'm exploring"; a free-text goal is interpreted by the AI (propose-only, the student's words fenced off as data) into a PENDING suggestion that changes nothing until the student accepts one career (as main or Plan B) or dismisses it; a new interpretation supersedes the old; an AI failure changes nothing. Routes authenticate the student and act only on that student (a body can't name one); the AI call is rate-limited (10/hour).
- **Regulation matching:** the roadmap now uses the curriculum for the student's regulation (case-insensitive) when it is known — never a different regulation's — with a distinct empty state, "no curriculum for your regulation". With no regulation set it uses the newest published curriculum, as before. **There is no student-facing way to set the regulation yet** (the column exists and the loader honours it; the setter belongs to the Phase 8 student page), so today only an operator can set it.
- **Tests:** 11 relevance, 11 capability, 6 intent-rule unit tests; 12 live tests (catalog integrity, DB refuses a requirement on a non-active skill, no browser client can write careers/intent/suggestions, intent rules and isolation between students, the whole suggest → accept/dismiss flow with stubbed AI, capability loader); 3 HTTP end-to-end tests of the student routes against the running server incl. one REAL model call and a prompt-injection attempt (intent unchanged whatever the model said); 7 roadmap live tests incl. regulation matching; static/guard tests (nothing client-writable; career/capability code never imports the AI provider; relevance is pure; every intent route authenticates first). 596 unit tests pass; `tsc` clean; eslint 0 errors on source dirs.
- **Not asserted:** what the real model suggests for a given goal (only that the result is structurally valid, catalog-only, and cannot change the intent). No UI for the student's career selector yet (Phase 8).
- **Judgement calls to review:** "Communication" resolves to *Technical Communication*; Product Designer's legacy "Visualization" resolves to *BI / Dashboarding* (arguably not what a designer means); the three careers that exist both here and in the legacy table (Data Analyst, Software Engineer, ML Engineer) now have different target numbers in the new tables than in the legacy one until Career Path migrates.

## Phase 6 — Catalogs and Arena skill tags: DONE
- **Migration 055** (applied). `certification_catalog` (+ `certification_skills`, `certification_careers` with the stored REQUIRED / RECOMMENDED / OPTIONAL relevance), `learning_catalog` (+ `learning_item_skills`; capability range `level_from`→`level_to`), `project_catalog` (+ `project_skills`) and `arena_challenge_skills`. Catalogs are read-only to clients; difficulty / cost / duration are NULL when unstated. A catalog item can only reference an ACTIVE skill (trigger).
- **Projects:** `AI_GENERATED` rows can only be a `RECOMMENDATION` for exactly one student (`for_student_id`) and can never be an `ACTIVE` catalog entry; `COLLEGE` projects must belong to a college; only live general (CAPABILIO/MENTOR) projects are publicly readable. Saving an AI recommendation is capped at 20 per student and changes no capability — completing a project is what will create evidence (Phase 7/8 flow).
- **Starts empty, honestly.** Nothing is invented. SkillStudio's catalog is mock data with no backend, so nothing was migrated from it. Only the two certifications already curated in `skill_area_resources` were carried over (provider taken from the title/URL; difficulty and cost NULL; relevance OPTIONAL — the weakest claim). `skill_area_resources` is untouched and still feeds today's roadmap engine.
- **Operator seed path:** `scripts/seed-catalogs.mjs <file.json> [--dry-run]` (+ `scripts/lib/catalog-seed.mjs`, format in `docs/catalog-seed-format.md`). The whole file is validated first; an unknown/inactive skill key or unknown career key stops the run before anything is written and lists every problem; re-running updates in place; AI-generated and college projects cannot be seeded; https URLs only.
- **Arena tagging:** `arena_challenge_skills` is derived **in the database** by a trigger (so existing and future challenges are covered): the linked skill of `skill_area_key`, plus each free-text tag that EXACTLY matches an active skill's name or alias — nothing fuzzy. ~60 clearly-correct aliases were added (e.g. DFS/BFS → Graph Algorithms, joins/aggregation → SQL, locks/threading → Operating Systems); ambiguous tags (parsing, JSON, formatting) are deliberately left unmapped. **Coverage today: 40 of 130 challenges are tagged** (the other 90 only carry tags we don't map); it grows as the taxonomy does.
- **Matching** (`lib/catalog/match.ts`, pure): `recommendLearning` (teaches the skill, overlaps the student's gap; best = can start now → reaches the target → moves them furthest → shorter), `recommendCertifications` (configured for THIS career and covering a gap; the label is the stored one, never inferred), `recommendProjects` (live general projects, the student's own college's, AI recommendations made for THAT student; ranked by gaps covered, easiest first), `recommendArena` (active challenges tagged with a gap skill, nearest the wanted difficulty). Each can only return what it was given — "nothing configured" is an empty result the roadmap will state plainly.
- **Tests:** 17 matching unit tests; 10 live tests (seed validation and refusal paths, dry run writes nothing, re-run updates in place, real-data recommendations, DB rules for AI/college projects / candidate skills / ranges / https, anon can read active items but not write and cannot see drafts or another student's AI recommendation, per-student recommendations and the cap, Arena trigger tagging/re-deriving/ignoring unknown tags); static + guard tests. 628 unit tests pass; `tsc` clean; eslint 0 errors on source dirs.
- **Not done / for later phases:** nothing consumes these catalogs yet (Phase 7 generates the roadmap from them); the AI that *writes* a project recommendation is Phase 7; the student flow that starts/completes a project and turns completion into evidence is Phase 7/8; there is no UI to maintain catalogs (operator-only by decision).
