# Production foundation: what must be true before "complete" means anything

Measured, not assumed. Run `npm run coverage:audit` and `npm run judge:health` for the current numbers.

## 1. Code execution (the platform's engine)
- Today the app falls back to the **shared public Wandbox** runner when `JUDGE0_URL` is not set. It has no SLA, is rate-limited, took 14 s for a Java
  hello-world in the last health run, and has no C#, Go, Rust or Kotlin. Not acceptable for proofs that colleges rely on.
- Deploy `infra/judge0` on a dedicated Linux host, private network only. Set `JUDGE0_URL` and `JUDGE0_TOKEN` in the app's environment, then run
  `npm run judge:health` until every language is `ok` and under about 5 s. Set `NEXT_PUBLIC_EXTRA_LANGUAGES=1` to offer Go, Rust, C# and Kotlin.
- Judge0 CE 1.13.1 needs cgroup v1 on the host (kernel boot option `systemd.unified_cgroup_hierarchy=0`) and runs its sandbox as privileged
  containers: use a host that runs nothing else. Check `GET <JUDGE0_URL>/languages` for the exact language list and versions on your instance.
- **C# and language versions:** Judge0 CE's stock C# is Mono (C# 7), Java 13, Python 3.8 and Node 12, all too old for the lessons. `infra/judge0/Dockerfile`
  adds Java 21, Python 3.12, Node 20 and .NET 10 as extra language ids (101 to 104); run `npm run runner:verify` after any runner change.
- Capacity: one worker handles one run at a time. Size workers to the number of students who may press Run together (a college exam is the worst
  case), and queue or rate-limit rather than fail.

## 2. Content correctness (the platform's trust)
- A lesson example, a problem or a workstation task is published only after it has been **executed and checked**. The LeetCode bank already does
  this (two independent solutions must agree). The language tracks do it for C, C++, Python, SQL and JavaScript examples (see
  `lib/languages/tracks.test.ts`); Java runs only with `LIVE_RUNNER=1`; HTML and C# examples are only structurally checked. Close those gaps.
- Nothing generated by AI is shown as authored: role lessons are generated when opened and cached, and are not reviewed. Treat them as drafts.

## 3. Measurement
- `npm run coverage:audit` reports learn, practise and prove per language track and per catalogue role, with thresholds as named constants.
  Known limit: practice tasks that are templates written in code are not counted (no registry yet). Build that registry next.

## 4. Operations and compliance (not yet audited)
- Observability on the runner and the AI calls, abuse and cost limits, backups, and handling of student data under India's DPDP Act still need an
  explicit review. They are listed here so they are not forgotten, not because they are done.
