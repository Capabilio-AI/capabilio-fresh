## 3. Stage 13: Capabilio Certificate (built) versus Skill Passport (separate)

Two different products, kept apart on purpose:

- **Skill Passport** (`/passport/[code]`, exists): internal badges and a portfolio the learner chooses to share.
- **Skill Certificate** (`/verify/[code]`, new): the recruiter-facing credential, like Udemy or Coursera but with evidence. It is signed (Ed25519, key `CREDENTIAL_SIGNING_KEY`,
  public key at `/api/credentials/public-key`), revocable by an admin (`decide` permission, audit-logged), and issued only when the server finds every module of a course proven.

What a recruiter sees:
1. Scan the QR code: the certificate page (valid / revoked / expired / does not verify), headline numbers, and **under the QR code the link to the evidence portfolio**.
2. `/verify/[code]/portfolio`: **only this certificate's evidence**: per module the test score of the passing attempt, the problem and language, hidden tests met, tries, dates, and
   the learner's own passing code **only if they chose to show it** (a SHA-256 in the signed record proves it is unchanged). It reads nothing else: a test fails if these pages
   touch the passport, profiles, badges, another course or the roadmap.

Evidence is recorded at the moment a module is proven (migration 215). Consent: name and code are separate choices at claim time; the code choice can be changed later (it is
not part of the signed record). Honest limits: evidence is the first passing attempt's score and test counts, not a replay; the PDF is the browser's "Save as PDF" of a print-styled
page; one credential per learner per course (a revoked one is not silently replaced); key rotation would need the old public keys kept.
